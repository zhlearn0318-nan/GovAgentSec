第三阶段 运行时数据分级访问控制项目总结
一、项目概述
对应赛题：数据安全评测・分级访问控制
难度等级：进阶级
预计耗时：4 小时
阶段定位：运行时动态安全防护层，作为第二阶段静态描述扫描的能力补充。静态扫描仅能检测文档明示风险，本阶段在 Skill 实际执行过程中对文件访问请求做强制校验，实现 “描述合规≠实际越权” 的兜底防护，构建 “静态前置筛查 + 运行时强制拦截” 的完整安全防护体系。
二、核心目标
数据分级标签化：建立四级数据安全分级体系，对受保护文件进行安全等级标记，分级标准对齐政务数据分类分级规范。
强制访问控制：基于 Skill 权限基线与数据安全等级，实现运行时越权访问自动拦截，严格遵循最小权限原则。
全程审计追溯：所有文件访问请求全量落盘日志，包含访问主体、访问客体、安全等级、决策结果与时间戳，满足安全审计要求。
低侵入部署：以中间件形式插拔式接入，无需修改 Skill 业务代码与原始数据文件。
三、系统架构
采用「配置驱动 + 中间件拦截 + 审计落盘」三层架构，无侵入式嵌入 Skill 运行链路：

四、分级与权限体系
1. 数据安全分级标准
采用四级分级机制，对应安全权重数值，数值越大安全等级越高。
表格
安全等级	安全权重	适用场景
公开	0	可公开披露的公示类、通知类数据
普通	1	内部一般性业务、日常办公类数据
敏感	2	用户隐私信息、业务敏感数据、内部涉密信息
绝密	3	核心密钥、凭证类最高等级数据
2. Skill 权限基线
为每个 Skill 分配最高可访问等级，权限默认向下兼容，遵循最小权限原则分配。通过独立配置文件管理，权限调整无需修改核心代码。
五、核心实现机制
1. 配置加载模块
启动时一次性加载数据分级表与 Skill 权限表，支持新增文件、新增 Skill 的热扩展，无需重启校验服务。
2. 分级决策模块
核心决策基于安全权重数值比较，逻辑严格且可预测：
访问允许 = 目标文件安全权重 ≤ 请求 Skill 权限权重
当目标文件安全等级高于 Skill 授权等级时，触发强制拦截，直接返回越权拒绝响应，请求不透传至业务层。
3. 审计日志模块
所有访问请求（含放行与拦截）全量落盘，记录字段包含：时间戳、Skill 名称、目标文件路径、文件安全等级、访问决策结果，满足安全审计追溯要求。
六、测试验证
采用四组典型场景覆盖测试，验证拦截有效性与业务可用性。
测试用例矩阵
表格
用例序号	请求 Skill	目标文件	预期结果	测试目的
1	普通业务 Skill	public.txt（公开级）	放行	验证低等级文件正常访问可用性
2	普通业务 Skill	user_privacy.txt（敏感级）	拦截	验证低权限越权访问高等级数据的阻断能力
3	授权隐私 Skill	user_privacy.txt（敏感级）	放行	验证匹配权限的正常业务访问能力
4	授权隐私 Skill	secret_key.txt（绝密级）	拦截	验证边界越权场景的阻断能力
验证结果
四组用例全部符合预期，两放两拦，越权访问 100% 拦截，授权访问 100% 放行，同时自动生成全量审计日志。
八、方案特点
低侵入性：中间件插拔式设计，无需修改 Skill 业务代码与原始数据文件，部署成本低。
强制访问控制：运行时强制拦截，不受 Skill 自身描述文档约束，覆盖隐藏越权行为，弥补静态扫描盲区。
配置化管理：分级规则与权限基线均为配置驱动，调整策略无需改动核心代码，运维灵活。
全程可审计：全量访问行为落盘追溯，符合等保 2.0 安全审计要求。
规范对齐：分级标准对齐政务数据分级分类规范，高度贴合赛题场景设定。
