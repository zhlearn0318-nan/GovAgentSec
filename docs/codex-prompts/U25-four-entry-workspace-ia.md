### 2.2 唯一登录与会话

- **全站唯一业务登录入口**：动态权限页。其它页若发现无委托：提示「先到动态权限登录」，一键 `navigate('permissions')`，**禁止**再嵌一套完整登录表单（极简「去登录」链接除外）。
- 登录 UI：账号 + 密码；演示环境角标「演示（非生产）」；管理员开启演示源的路径保留（未开启时说明由管理员在防护设置/配置与维护开启，用户不猜网关令牌）。
- 会话：继续 `identity-session.mjs` 闭包持有 token；不进 `localStorage` / URL / DOM 明文；刷新丢内存委托的现有语义保持诚实文案。
- 登录成功：身份、角色、可执行权限、材料可见范围与现网 ACL 一致；顶栏徽章全局更新；待审批角标可用。
- 退出 / 切换账号：撤销旧委托再签新；禁自批与双人审批仍要求 **审批人独立上下文**（可独立标签页），不要为演示偷偷保留经办权。

### 2.3 动态权限页信息架构

登录后主区至少：

1. 当前员工：显示名、角色、权限摘要（可读材料密级、可调工具族、是否可批、是否可改准入规则）——**摘要来自服务端**，前端不自制权限。
2. 待审批队列：待我处理 / 我发起的 /（可选）全部可见；卡片含申请人、动作/材料、越权原因、批准≠执行状态；深链 `request_id`。
3. （若并入）当前任务绑定与材料范围摘要、返回原任务。

### 2.4 能力准入页
