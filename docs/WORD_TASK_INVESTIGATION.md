# Word 模板任务：误拦、阻断与耗时调查

核验时间：2026-11-05。任务：帮我制作一个报账 word 模板。
轨迹：`b0e17209b1f0553661fa7535f3fdb844`。本报告调查既有运行，不代表修复已部署。

## 结论

当前问题主要在 GovAgentSec 的运行接入与观测设计：工具返回包装会触发误判；工具内容隔离没有连接任务取消；普通工具异常、格式不支持与安全威胁被混记；没有对话内主动告警。任务变慢同时受模型执行策略、文档运行环境和防护调用链影响，不能只归因于基础模型或 OpenClaw。

## 1. BLOCK 为什么仍继续

`result-gate.mjs` 对非 ALLOW 的工具返回只返回安全占位结果，没有调用宿主任务取消接口。模型看到工具出错后可以继续推理、换工具重试。工具的外部副作用发生在返回检查之前，因此写入也不会被撤销。

`guard-events.mjs` 却把一次工具阶段失败升级为整个运行的 blocked，并停止该状态的后续更新。`ui/inject.js` 仅更新侧栏，没有对话内告警或阻断说明。它们共同造成“显示已拦截，实际仍生成”的错觉。

第一次工具返回 BLOCK 后，轨迹记录了 25 次后续模型调用。输入门控和工具返回门控是不同边界；本任务输入实际为 ALLOW。

## 2. 正常任务的五次 BLOCK

| 阶段 | 已确认情况 |
|---|---|
| read 读取报账 CSV | 正常表格；回放同一内容时正文 ALLOW、工具 JSON 包装 BLOCK，可复现接入误判 |
| exec 再次读取同一 CSV | 紧随第一次隔离的换工具重试；同一内容的包装误判已复现，原始返回被替换，历史完整包装未保留 |
| read 读取预览 PNG | 返回门控只支持文本，图片被本地适配器拒绝；这是能力不支持，不能等同于已发现严重攻击 |
| exec 检查 PDF 布局 | 历史原始返回及具体原因未保留，不能准确追溯到某个检测器或异常分支 |
| edit 调整模板脚本 | 同样缺少历史具体原因，不能据 BLOCK 标签断言代码危险；之后模型又继续检查、修改和生成 |

独立诊断会话的真实服务回放（避免多轮状态互相影响）：

| 输入给工具返回检测器的材料 | 判定 | 耗时 |
|---|---|---:|
| CSV 原文 | ALLOW，LOW | 655 ms |
| CSV 的 `{content:[{type:'text',text:...}]}` 包装 | BLOCK，CRITICAL，prompt_injection | 931 ms |
| “工具返回正文”标签 + CSV 原文 | ALLOW，LOW | 692 ms |
| 包装后的“正常查询结果” | BLOCK，CRITICAL，prompt_injection | 696 ms |
| 明确要求忽略指令并泄露密钥的文本 | BLOCK，CRITICAL | 1,025 ms |

这组结果证明接入协议包装与检测输入不匹配，不能用降低全局安全阈值来修复。目前接口没有返回逐检测器证据，无法仅凭响应判断具体是哪一个底层检测器首先误判。

另外，`executeWithResultGuard` 将工具抛错、结果超长、非文本、检测异常都转成同类隔离；`recordFailure` 丢弃了传入的原因，并统一写入 CRITICAL/BLOCK。轨迹又只保留 decision/enforced/riskLevel/at。历史审计不足是本次无法完全还原最后两次拦截的直接原因。

## 3. 时间用在哪里

任务从 16:58:04 到约 17:05:13，墙钟耗时 428.6 秒。28 次模型调用、28 次工具调用。

| 观测项 | 时间 | 解释 |
|---|---:|---|
| 模型调用累计 | 86.9 秒 | 包含模型服务响应时间；平均约 3.1 秒/次，不能等同纯推理时间 |
| 工具调用累计 | 345.7 秒 | 包含工具前后钩子及宿主开销，与模型阶段可能重叠，不可直接和上一项相加 |
| 工具前检查时间窗口累计 | 29.7 秒 | 从工具开始事件到防护决策，包含该窗口的调度开销 |
| 临时 pip 安装依赖的进程时间 | 52.3 秒 | 文档环境未准备好，任务中途安装 |
| 三次 Word/PDF 预览相关进程时间 | 123.2 秒 | 分别约 37.2、43.0、43.1 秒，反复启动 Word 并导出预览 |
| 19 个有进程计时的 exec：外层减进程时间 | 116.4 秒 | 包含防护、宿主及调度，现有日志不能把它全部算作安全模型耗时 |

可确认的额外返工：CSV 隔离后换命令重新读取；图片无法返回后转为 PDF 文本/坐标检查；模型在 PowerShell 中生成 Bash heredoc 命令，直接语法失败；后续检查脚本出现 `max() iterable argument is empty`。这些是执行策略和环境适配问题。

没有做同一模型、同一输入的完整开关防护对照，不能宣称“关闭系统会快几倍”。小文本检测回放为 0.3–1.0 秒量级；这也不代表长命令、大返回或并发负载的耗时。

## 4. 修复顺序与验收标准

1. **阻断闭环**：明确 BLOCK 是否终止当前任务；要终止时调用宿主取消、禁止后续工具，并记录实际取消结果，不能把“已请求取消”写成“已停止”。在对话内显示阶段、原因、后续操作。
2. **判定输入适配**：分离工具协议与业务内容，对各文本块、结构化字段、附件按类型检查；保持全量覆盖，避免只检查前缀或默许图片。CSV、正常 JSON、中文表格、代码差异、工具报错、图片分别进入回归集，同时保留注入攻击测试。
3. **区分原因**：风险命中、检测超时、服务故障、结果不支持、工具执行错误分开记录与展示；保存规则/检测器、原因代码和耗时，不将所有异常标成 CRITICAL。
4. **性能归因**：为工具执行、前检查、返回检查、输出复检分别计时；相同固定工具样本做启用/停用防护对照，报告延迟分布。全任务对照需考虑模型行为变化。
5. **文档任务路径**：准备稳定的 Python/Word/PDF 环境，固定 Windows 命令写法，减少临时安装和不必要的重复渲染；遇到安全终止立即结束当前尝试，避免继续消耗调用。

本机证据（不提交仓库）：`local-validation/word-investigation.json`、`word-timing.json`、`word-replay.json`、`word-replay-independent.json`。原始轨迹未改写。
## 2026-11-05 修复验收

本节记录本轮实际修复，不改写上文原始调查结论。

- 工具返回检测改为正文和附加字段的语义文本，避免协议 JSON 转义造成误判；重复的 exec aggregated 正文只检测一次，仍覆盖未知字段与多个内容块，不截断后放行。
- 工具阶段 BLOCK/需复核、不支持的内容和检查不可用会请求宿主取消当前任务，后续工具调用被拒绝。任务结束事件到达后才显示“当前任务已停止”。这不会撤销工具在返回审查前已经完成的写入。
- 普通工具异常经过内容检查后返回，单独标记工具执行错误；不会仅因为 Python/文件操作报错就认定严重攻击。
- 对话顶部新增持续可见告警，显示阶段、中文原因、原因代码及停止确认。切换会话清理旧提示，忽略迟到的旧会话响应；侧栏隐藏时告警仍可见。
- 轨迹新增原因代码、风险类别、检测耗时、工具执行耗时。工具阶段取消等待宿主最终输出事件后封存，避免取消后最后事件使哈希清单失配。
- 设置子面板支持“重新加载”，重新签发一次性访问凭据；失效面板返回中文恢复页，API 的匿名访问仍为 401。

验证：93 项相关 Node 测试通过（包含取消、审批超时、封存顺序回归）；真实宿主取消接口、会话内告警浏览器回归、设置返回/重载回归通过。真实模型样本中，CSV、带 exec 元信息 CSV、代码差异和普通文件错误均 ALLOW，攻击文本 BLOCK；本次小样本检测 286–508 ms。不能将其解释为全任务性能提升比例。

实际聊天验证：输入 ALLOW，读取无害测试文件中的攻击文本后工具返回 BLOCK，调用宿主取消；之后新增模型/工具调用均为 0，任务结束、告警和封存轨迹均可核验。证据：`local-validation/delivery/live-tool-stop.json` 与 `tool-block-stopped.png`。

仍有明确边界：当前检测器不支持图片，图片返回将提示“不支持”并中止，不再伪称发现攻击；聊天已发送的流式回复不能撤回，输出复检不等于完整发送前门控。完整文档任务的性能取决于模型调用次数、命令执行和预览策略，本轮未用降低安全阈值换取速度。

补充：端到端文档验证发现，现有 highImpactTools 策略对 exec/write/edit 等操作要求逐次确认，未确认会等待 60 秒。已新增“等待操作确认”告警和审批等待耗时；超时/拒绝会请求停止任务，避免模型重试再等待。未移除或放宽该审批规则。

正常文档端到端测试通过：在现有审批策略下对隔离测试操作逐次允许一次，4 次模型调用、4 次工具调用，约 36.3 秒生成有效 DOCX，姓名/部门/日期/金额/备注字段存在，无安全 BLOCK。测试要求一次生成、不安装依赖、不转 PDF、不做预览，因此不是与原始七分钟任务同条件的提速对照。证据：`local-validation/delivery/word-task-fixed.json`。
