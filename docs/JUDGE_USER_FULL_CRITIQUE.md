# GovAgentSec 全流程体验评审

体验于2026-11-08，整理交付于2026-11-09，U22/U23后复审。此文保留当时只读评审的问题快照；用户随后授权的改版实现与测试见[U24实施记录](U24_PRODUCT_FLOW_IMPLEMENTATION.md)，不要把下列全部缺点当作当前状态。此前版本保存在评审证据目录的 `.before` 文件中。

## 1. 评审结论

**已具备有证据的安全能力，尚未形成普通用户能独立完成的连续产品流程。适合有准备的技术演示，暂不宜直接宣称“全流程实时、自动、安全自演进的政务办公系统”。**

评委能看见真实阻断、一次性授权、隔离执行和可追溯候选，这些是项目的价值。用户目前仍要理解网关令牌、业务委托、路径授权、两种审批、历史轨迹、命令行评审。下一步优先把这些能力组织成一次任务，不宜继续增加平行面板。

四层能力作为评委的观察框架；用户主路径是：**登录 → 选择任务和材料 → 执行 → 处理权限或风险 → 得到结果 → 查看过程 → 从同类历史任务提炼候选。**

## 4. 实际用户路径与断点

| 阶段 | 当前操作 | 断点 | 目标行为 |
|---|---|---|---|
| 进入 | 网关连接→业务登录→开启演示源→选角色 | 用户接触部署凭证和管理员动作 | 管理员准备环境；用户单一业务入口 |
| 开始 | 选聊天→开始任务→确认绑定→回聊天描述路径 | 绑定不等于材料授权 | 任务模板＋材料＋范围摘要，一次确认 |
| 执行 | 聊天工具折叠行＋侧栏检测链 | 业务进度与安全状态分散 | 对话旁显示当前动作、状态和结果 |
| 扩权 | 被拒→申请→另页审批→回原聊天重试 | 短TTL；硬拒绝/可申请必须区分 | 单卡展示请求、审批人、时效和返回 |
| 查过程 | 左侧轨迹/顶栏轨迹/任务抽屉/旧历史 | 入口范围不明；新旧渲染切换 | 当前任务一个过程入口；历史归审计 |
| 学习 | 手填key→CLI评审→对比→生成→准入 | UI断流；勾选集合与生成全集不同 | 任务组→评估→筛选→候选→准入→复核 |

本轮不把分项PASS拼成“一个自然语言业务任务已从头到尾连续完成”。尚缺真实结果可打开、来源可核对、无需CLI补步骤的一镜到底排练。

## 6. 视觉与信息架构

界面比早期多窗口已收敛，但仍像工程工作台：约258px侧栏、双层顶栏、主标题、按钮、说明和警告之后才到结果。1440×1000真实图首屏从约670px开始；可视宽852px、画布宽1000px，内容高2058px。18事件就需双向滚动；JSON详情进一步挤窄。

保留现有青绿和OpenClaw聊天主体，改为任务工作区：任务、身份与范围一行；中央结果和对话；右侧只在待处理/查看过程时出现。默认5–8个关键节点，可展开全量事件。不能靠删风险或画假边简化。

首屏用“本任务可读2份材料”“需要审批”“已获一次授权，等待重试”“已完成，查看来源”。scope_digest、SHA、JSONL、Uxx、论文阈值、平台限制进技术详情或独立边界文档。
